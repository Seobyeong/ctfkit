# ROADMAP

ctfkit 개발 계획. 각 단계는 **통과 조건(Gate)** 을 만족해야 다음 단계로 넘어간다.
> 원칙: 미완성인 큰 프로젝트보다, 완성된 중간 규모 프로젝트가 낫다.
> Gate를 통과하지 못하면 다음 버전으로 가지 않고 현재 버전을 마무리한다.

## 방향 (2026-11-10 재설정)

**AI 에이전트가 CTF 문제를 풀 때 쓰는 토큰과 시간을 줄이는 도구.**

에이전트(Claude Code 등)는 도구가 없으면 풀이 코드를 매번 직접 쓰고, 결과를 읽고, 다시 쓴다.
ctfkit 은 그 반복을 짧은 명령 하나로 바꾼다. 얼마나 줄였는지는 주장하지 않고 **측정해서** 보여 준다.

- **측정이 먼저다.** 모든 개선은 [벤치마크](../bench/README.md) 수치로 확인한다. 수치가 나아지지 않는 변경은 넣지 않는다.
- **줄일 대상은 세 가지다.** 호출 수(왕복), 작성 토큰(에이전트가 쓰는 명령·코드), 읽기 토큰(에이전트가 읽는 출력).
- **AI API 를 직접 호출하지 않는다.** ctfkit 은 에이전트가 쓰는 도구이지 에이전트가 아니다. API 키와 비용 없이 누구나 설치해 쓰고 벤치마크를 재현할 수 있다.
- **사람도 그대로 쓴다.** CLI 와 그래픽 화면(`ui`)은 유지한다. 에이전트에 좋은 출력(짧고 답에 가까운 출력)은 파이프에도 좋다.
- **의존성 선:** 표준 라이브러리로 되는 기능이 기본. 무거운 분석은 선택 의존성(`[image]`, `[rev]`)으로 분리한다.
- **안전 범위:** `web` 은 허용 도메인(워게임 인스턴스·localhost) 전용·속도 제한 유지. `rev`/`pwn` 은 로컬 파일 정적 분석과 오프셋·가젯 계산까지만 다룬다.
- **마감:** 2026-12-06 (일) 23:59

### 이전 방향에서 바뀐 것

이전 방향은 "드림핵 전 분야를 넓게, 그다음 깊게" 였다. 분야별 기본기(Phase 1)는 v0.11~v0.15 로 끝났고,
분야별 심화(Phase 2)는 여기서 중단한다. 기능을 더 늘리는 대신, 이미 있는 13개 명령을 에이전트가 싸게 쓸 수 있게 다듬는다.

## 개발 방식

수업에서 강조한 "AI로 작성된 코드를 리뷰·수정·개선하는 개발"을 그대로 따른다.

1. **AI 작성:** 기능 단위로 AI(Claude Code)가 코드와 테스트를 작성한다.
2. **사람 리뷰:** 내가 코드를 읽고 이해한 뒤, 버그·설계 문제·이해 안 되는 부분을 리뷰로 남긴다.
3. **수정·개선 요청:** 리뷰 결과와 추가하고 싶은 기능을 AI에 요청하고, 반영된 결과를 다시 리뷰한다.
4. **측정:** 변경 전후로 `python bench/run.py` 를 돌려 수치를 비교한다.
5. **기록:** 매 사이클마다 devlog에 *요청한 것 / 리뷰에서 발견한 것 / 배운 것 / 수치 변화*를 남긴다.

> README에 AI 활용 사실과 참고한 기존 도구(CyberChef "Magic", Ciphey, curl, binwalk, jwt_tool, pwntools, checksec, radare2 등)를 명시한다.

## 측정의 원칙

- **비교 대상을 약하게 만들지 않는다.** 표준 라이브러리 코드는 플래그 형식으로 걸러 필요한 줄만 출력하고, 풀이 방법을 미리 안다고 가정한다.
- **불리한 과제를 빼지 않는다.** ctfkit 이 더 나쁜 과제도 표에 남긴다.
- **추정은 추정이라고 적는다.** 토큰은 바이트 수 / 4 추정값이고, 모델이 생각하는 시간은 재지 않는다.
- **벤치마크에 맞춰 도구를 고치지 않는다.** 과제 13개에서만 통하는 처리(특정 입력 하드코딩 등)는 넣지 않는다. 새 과제를 추가했을 때도 같은 경향이 나와야 한다.

## 알려진 한계

- **짧은 비즈네르 암호문:** 75바이트 안팎까지 1순위로 복구한다. ~50바이트에 긴 키 조합은 일부 글자가 틀릴 수 있다.
- **XOR 다중 바이트 키:** 대략 데이터 길이의 1/50 길이 키까지 안정적이다.
- **점수 함수의 임계값**(`SOLVED_THRESHOLD`, XOR `ENGLISH_THRESHOLD` 등)은 예제로 맞춘 값이다.
- **실행 시간:** 명령 하나에 0.14~0.2초가 걸린다(파이썬 자체는 0.11초). 남은 차이는 argparse 와 패키지 import 다.
  개발용 설치(`pip install -e`)에서는 파이썬 시작 자체가 0.06초가량 더 느리다(양쪽 방법 모두 같은 영향).
- **`web` 안전성:** 허용 도메인 목록 밖으로는 요청을 보내지 않고, 반복 요청에 속도 제한과 총량 상한을 둔다.
- **`rev`/`pwn` 범위:** 로컬 파일 정적 분석과 오프셋·가젯 계산까지. 원격 서비스 자동 익스플로잇은 다루지 않는다.

## 보류 (이번 마감 범위 밖)

방향을 바꾸면서 내려놓은 항목. 마감 뒤에 다시 볼 수 있게 적어 둔다.

- 치환 암호 풀이 (쿼드그램 + 대용량 코퍼스 필요)
- RSA 추가 공격: 작은 e 세제곱근, Hastad 브로드캐스트
- web SQLi/LFI 탐색 헬퍼, 세션·CSRF 토큰 추적
- 스테가노 심화(다중 LSB·팔레트), 파일 복구 강화
- 심볼 없는 함수 그래프, 자동 ROP 체인 구성
- `auto` 탐색 과정 트리 출력, TUI
- workspace 노트 → Markdown 리포트
- MCP 서버(argparse 스키마에서 에이전트용 도구 목록 자동 생성), AI API 직접 연동
- 웹 플레이그라운드(Pyodide)
