# 실전 기록 (fieldlog)

실제 문제를 ctfkit 으로 풀면서 **도운 것과 막힌 것**을 적는다. "막힌 것" 이 곧 v0.30 의 작업 목록이다 (ROADMAP 6절).

- 대상: 드림핵 워게임, picoCTF 연습 문제. 하루 한두 문제.
- **플래그와 풀이 전문은 적지 않는다.** 저장소는 공개돼 있다. "어떤 형태의 입력에서 무엇이 안 됐는가" 만 적는다.
- 추측으로 기능을 만들지 않는다. 여기 적힌 막힌 것만 고친다.
- v0.30 통과 조건: **10문제 이상**, 막힌 것 중 ctfkit 범위 안의 것은 고쳤거나 안 고친 이유를 적는다.

만들 수 없다. ctfkit 의 자동화가 닿는 범위 밖이라 측정에서 뺀다 (삭제한 GUI 패치 문제와 같은 판단).

## 1. 2026-11-17 — 암호(RSA), 드림핵

- 처음 실행한 명령: `ctfkit start <다운로드한 zip>`
- ctfkit 이 한 것: zip 을 풀어 `challenge.py` 하나를 찾고, 글자 파일이라고 요약했다.
- 막힌 것:
  1. 다음 단계로 `forensic strings challenge.py --grep <정규식>` 을 권했다. 플래그는 서버에 있으므로 쓸모가 없다.
     요약도 소스 첫 줄(`#!/usr/bin/python3
from Crypto...`)을 잘라 보여 줄 뿐이었다.
     - 입력 형태: PyCryptodome 으로 RSA 를 만들고 `input()` 으로 메뉴를 받는 서버 소스
  2. 작업 폴더 이름에 브라우저가 붙인 ` (1)` 이 그대로 들어갔다 (같은 파일을 두 번 받은 경우).
  3. 서버(nc)에 접속해 N·e·c 를 받아야 하는 문제다. `template rsa` 는 값이 이미 있는 문제용이라 원격 문제에는 맞지 않는다.
- 처리:
  1. 고침(v0.30): `ctfkit/source.py` — 소스 코드를 알아보고 언어·단서(쓰는 라이브러리, 소수 크기, e, 입력 여부, 플래그 파일,
     함수 이름)를 보여 준다. 분야에 맞는 명령(이 경우 `rsa decrypt`, `template rsa`)이 있으면 strings 대신 그것을 권한다.
     공격 방법은 추측하지 않는다.
  2. 고침(v0.30): 기본 이름에서 ` (N)` 을 떼고, 이미 있는 이름이면 `-2`, `-3` 을 붙인다.
  3. 보류 → 3번 문제에서 같은 형태가 다시 나와 고침(v0.30): `template remote`.
- 결과: 넘어감. 서버에 netcat 으로 접속해야 하는 문제라 나중에 다시 본다.

## 2. 2026-11-17 — misc(파일 변환), 드림핵

- 처음 실행한 명령: `ctfkit start <다운로드한 zip>`
- ctfkit 이 한 것: zip 을 풀어 변환 스크립트와 결과 파일을 찾았다. 스크립트에서는 "플래그 파일이 이미지" 라는 것만 보여 줬다.
- 막힌 것:
  1. 결과 파일은 148KB 의 hex 글자였다. triage 는 4KB 이하의 글자만 auto 로 해독해 보므로 아무것도 하지 않았다.
     auto 가 해독했더라도 찾는 것은 글자 플래그라서, 플래그가 그림으로 들어 있는 이미지는 찾을 수 없다.
     - 입력 형태: 이미지 파일의 바이트마다 같은 수를 더한(mod 256) 뒤 대문자 hex 로 적은 글자 파일
  2. 스크립트의 핵심(바이트마다 더하기, hex 로 적기)을 단서로 보여 주지 않았다.
  3. 다음 단계가 `forensic strings` 하나뿐이었다.
- 처리:
  1. 고침(v0.30): `ctfkit/recover.py` — hex·base64 로 읽고, 바이트마다 XOR·덧셈·뒤집기를 시도해 맨 앞이 알려진 파일 머리
     (PNG·ZIP·PDF 등)와 맞으면 되살린다. 키는 머리 첫 바이트로 계산하므로 크기와 관계없이 빠르다. 무작위 데이터 60개에서 오탐 없음.
     `start` 는 되살린 파일을 `이름.recovered.png` 로 저장해 이어서 분석하고 "열어 볼 파일" 로 알려 준다.
     따로 쓸 때는 `ctfkit forensic recover FILE -o out.png`.
  2. 고침(v0.30): 소스 단서에 "나머지 연산으로 값 회전 +N", "hex 글자로 변환" 을 더했다.
  3. 1 로 해결: 되살린 PNG 에 `forensic lsb` 를 권한다.
- 결과: 풀었음. `start` 한 번으로 이미지를 되살렸고, 되살린 이미지를 열어 플래그를 확인했다.

## 3. 2026-11-17 — 암호(블록 암호), 드림핵

- 처음 실행한 명령: `ctfkit start <다운로드한 zip>`
- ctfkit 이 한 것: 서버 소스 하나를 찾고 단서(DES, ECB 모드, hex, 입력을 받음, 플래그 파일)를 보여 줬다.
- 막힌 것:
  1. 분야별 명령이 없어(CBC 가 아닌 블록 암호) 다음 단계가 `forensic strings` 로 돌아갔다. 소스에는 쓸모없다.
  2. 풀이 방향을 정하는 데 필요한 사실 몇 가지를 단서로 보여 주지 않았다: 서버의 시간 제한(`signal.alarm`),
     무작위로 만드는 바이트 수, 암호 객체를 몇 개 만드는지.
  3. 1번 문제와 같이 nc 로 접속해 값을 받고 답을 보내는 문제다. 세 문제 중 두 번째라 보류를 풀었다.
     - 입력 형태: `print(f"안내 {값}")` 로 값을 주고 `input("안내 > ")` 로 답을 받는 파이썬 서버
- 처리:
  1·3. 고침(v0.30): `ctfkit template remote SRC [--host --port]` — 서버 소스(파이썬)를 ast 로 읽어 값을 주는 print 와
     입력을 받는 input 을 나온 순서대로 소켓 코드로 옮긴다. 표준 라이브러리만 써서 pwntools 가 없는 윈도에서도 돈다.
     입력을 받는 파이썬 소스면 `다음` 의 첫 줄로 권한다.
  2. 고침(v0.30): 단서에 "시간 제한 N초", "무작위 N바이트", "암호 객체 N개" 를 더했다. 공격 방법은 여전히 적지 않는다.
- 결과: 진행 중

## 5. 2026-11-26 — 리버싱(윈도우 PE), 드림핵 평가용

- 처음 실행한 명령: `ctfkit start <zip>` (에이전트 B)
- ctfkit 이 한 것: zip 을 풀고 PE 64비트 실행 파일로 알아봤다. `다음` 으로 `rev disasm` 을 권했다.
- 막힌 것:
  1. 플래그를 찾지 못했다. 바이너리에는 입력과 비교하는 문자열이 평문으로 있지만 `DH{` 접두사가 없는 알맹이뿐이라
     플래그 모양 검사에 걸리지 않았다.
     - 입력 형태: 입력을 `strcmp` 로 비교하는 윈도우 PE. 비교 문자열은 평문, 플래그 형식(`DH{...}`)은 문제 설명에만 있음
  2. 리버싱 문제인데 `다음` 둘째 줄로 `pwn rop` 을 권했다. 실행 파일이면 분야를 가리지 않고 같은 목록을 낸다.
- 처리: 1 은 접두사 없는 글자를 플래그 후보로 올리면 오탐이 크게 늘어 그대로 둔다.
  2 는 고침 (11/26 밤, 사용자 요청): `pwn rop` 은 ELF 에만 권한다. 평가용이라 재측정하지 않았다.
  2 는 "PE·입력 비교만 있고 취약 함수 단서가 없으면 pwn 명령을 뒤로" 라는 일반 규칙으로 쓸 수 있어 후보로 남긴다.
- 결과: 풀었음 (A 3/3, B 3/3). B 가 ctfkit 명령을 세 번 부르고 직접 한 번 더 봐서 비용 +31%.

## 6. 2026-11-26 — misc(원격 응답), 드림핵 평가용

- 처음 실행한 명령: `ctfkit start <zip>` (에이전트 B). 서버는 WSL 의 `socat` 으로 띄웠다.
- ctfkit 이 한 것: 바이너리·C 소스·핸드아웃 플래그 파일을 펼쳤다. 소스 단서로 난수 사용, 입력을 받음(nc 문제일 가능성), 시간 제한을 보여 줬다.
  핸드아웃의 플래그 파일은 형식 예시(가짜)로 보고 플래그에서 뺐다.
- 막힌 것:
  1. `다음` 이 `template pwn`, `rev disasm`, `pwn rop`, `pwn cyclic` 이었다. 값을 받아 계산해 돌려주는 문제라 쓸모가 없다.
     `template remote` 는 파이썬 서버 소스만 읽으므로 C 소스에는 권하지 않았다.
     - 입력 형태: 산수 문제를 여러 번 보내고 답을 받는 C 서버 (소스 제공)
- 처리: 고침 (11/26 밤, 사용자 요청). `pwn cyclic` 은 C 소스에 메모리를 넘칠 입력(gets·strcpy·scanf(%s)·read(0,…) 등)이 보일 때만 권하고,
  같은 문제의 C 소스에 그런 입력이 없으면 바이너리 형식에서 나온 `pwn rop`·`pwn cyclic` 도 뺀다 (`template pwn` 은 원격 응답 뼈대라 남긴다).
  `system` 은 메모리 위험이 아니라 판단에서 뺐다 (`system("cat flag")` 가 흔하다). 평가용이라 재측정하지 않았다.
- 결과: 풀었음. **A 는 3번 중 2번 방향을 못 잡고 일찍 포기(1/3), B 는 3/3.** 권한 명령은 틀렸지만 파일과 단서를 한 번에 보여 준 것이 도움이 됐다.

## 8~11. 2026-11-26 — 포렌식 4문제, 드림핵 평가용 (기준 커밋 a35aa81)

- 정답은 개발자가 그 커밋에서 코드를 고치지 않고 풀었고, 사용자가 드림핵에 제출해 4개 모두 맞았다.

- 막힌 것 (입력 형태):
