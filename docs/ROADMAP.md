# ROADMAP

ctfkit 개발 계획. 각 단계는 **통과 조건(Gate)** 을 만족해야 다음 단계로 넘어간다.
> 원칙: 미완성인 큰 프로젝트보다, 완성된 중간 규모 프로젝트가 낫다.
> Gate를 통과하지 못하면 다음 버전으로 가지 않고 현재 버전을 마무리한다.

## 방향 (2026-11-10 재설정)

**드림핵에 나오는 모든 분야(웹·암호·포렌식·리버싱·포너블·misc)를 한 CLI에서 다룬다.**
전략은 **넓이 먼저, 그다음 깊이**:

1. **넓이 (Phase 1):** 각 분야를 "기본 문제는 ctfkit 만으로 손댈 수 있다" 수준까지 먼저 채운다.
   완벽한 한 분야보다, 모든 분야에 쓸 만한 기본기가 있는 상태를 먼저 만든다.
2. **깊이 (Phase 2):** 넓이가 갖춰진 뒤, 분야별로 더 어려운 문제를 풀 수 있게 알고리즘·공격 기법을 심화한다.

단순히 동작하는 데 그치지 않고, 포트폴리오로 내보일 수 있는 품질(플러그인 구조, 테스트, 문서, 패키징)까지 목표로 한다.

- **공유 구조:** 모든 모듈이 같은 플러그인 레지스트리를 공유한다. 디코더·분석기·명령 하나 추가가 작게 끝나도록 설계해, 범용성은 구조의 부산물로 얻는다.
- **의존성 선:** 표준 라이브러리로 되는 기능이 기본. 무거운 분석(디스어셈블 등)은 **선택 의존성**(`pip install ctfkit[rev]` 등)으로 분리해 설치 부담 없이 쓰게 한다.
- **안전 범위:** `web` 은 허용 도메인(워게임 인스턴스·localhost) 전용·속도 제한 유지. `rev`/`pwn` 은 **로컬 파일 정적 분석**과 오프셋·가젯 계산까지만 다루고, 원격 익스플로잇 자동화는 학습 범위 밖으로 둔다.
- **마감:** 2026-12-06 (일) 23:59

## 개발 방식

수업에서 강조한 "AI로 작성된 코드를 리뷰·수정·개선하는 개발"을 그대로 따른다.

1. **AI 작성:** 기능 단위로 AI(Claude Code)가 코드와 테스트를 작성한다.
2. **사람 리뷰:** 내가 코드를 읽고 이해한 뒤, 버그·설계 문제·이해 안 되는 부분을 리뷰로 남긴다.
3. **수정·개선 요청:** 리뷰 결과와 추가하고 싶은 기능을 AI에 요청하고, 반영된 결과를 다시 리뷰한다.
4. **기록:** 매 사이클마다 devlog에 *요청한 것 / 리뷰에서 발견한 것 / 배운 것*을 남긴다.

> README에 AI 활용 사실과 참고한 기존 도구(CyberChef "Magic", Ciphey, curl, binwalk, jwt_tool, pwntools, checksec, radare2 등)를 명시한다.

## Phase 2 — 분야별 심화 (깊이)

Phase 1 Gate 통과 후 착수. 어느 분야부터 팔지는 Phase 1 이 끝난 시점의 남은 시간·관심으로 정한다.

| 분야 | 심화 후보 |
| --- | --- |
| auto/crack | 빔서치 튜닝, 비즈네르 hill climbing·쿼드그램 점수, 치환암호 빈도 분석, XOR 키길이 해밍거리 추정 |
| crypto | RSA 기초(공통 모듈러스·작은 e·Wiener), 더 많은 블록 암호 공격 패턴 |
| web | SQLi/LFI 탐색 헬퍼, 응답 diff 자동 판정, 세션·CSRF 토큰 추적 |
| forensic | 스테가노 심화(다중 LSB·팔레트), 파일 복구(carving) 강화 |
| rev/pwn | 심볼 없는 함수 그래프, pwntools 연동, 자동 ROP 체인 구성 |

> 심화는 [알려진 한계](#알려진-한계-깊게-팔-후보) 항목을 하나씩 해소하는 방향으로 진행한다.

## 알려진 한계 (깊게 팔 후보)

- **짧은 비즈네르 암호문:** 약 250바이트 이상이면 대부분 풀리지만, 100바이트 안팎에서는 열마다 글자가 적어 카이제곱이 불안정하고 키 일부가 틀린다.
  개선 후보: 바이그램·쿼드그램 통계로 점수 매기기, 키를 한 글자씩 바꿔 보며 점수를 올리는 언덕 오르기(hill climbing).
- **짧은 플래그만 XOR 된 경우:** 플래그 접두사로 시작하면 알려진 평문 공격으로 풀리지만, 접두사가 없거나 중간에 있으면 통계적 추정이 약하다.
- **점수 함수의 임계값**(`SOLVED_THRESHOLD`, XOR `ENGLISH_THRESHOLD` 등)은 예제로 맞춘 값이다. 더 많은 실제 문제로 검증이 필요하다.
- **`web` 안전성:** 허용 도메인 목록(워게임 인스턴스·localhost) 밖으로는 요청을 보내지 않고, 반복 요청에 속도 제한과 총량 상한을 둔다. 학습 목적 외 사용은 하지 않는다.
- **`rev`/`pwn` 범위:** 로컬 파일 정적 분석과 오프셋·가젯 계산까지. 원격 서비스 자동 익스플로잇은 다루지 않는다.

## 구현 예정 (Planned / 백로그)

지금 당장 만들지 않지만 잊지 않기 위해 적어 두는 항목들. 각 항목은 착수할 때 브랜치를 판다.

### jwt (Phase 1 · v0.11)
- [ ] `jwt decode`: 헤더·페이로드 디코드 (서명 검증 없이)
- [ ] `jwt forge --none`: `alg:none` 서명 없는 변조 토큰 생성
- [ ] `jwt crack`: HS256 약한 시크릿 사전 공격

### rev (Phase 1 · v0.12)
- [ ] `rev info`: ELF/PE 아키텍처·엔디언·섹션·심볼 요약
- [ ] `rev strings`: 섹션별 문자열 (forensic strings 와 별개로 바이너리 특화)
- [ ] `rev disasm`: 함수/주소 범위 디스어셈블 (capstone, 선택 의존성)

### pwn (Phase 1 · v0.13)
- [ ] `pwn checksec`: NX/PIE/Canary/RELRO 확인
- [ ] `pwn cyclic`: de Bruijn 패턴 생성·오프셋 역산
- [ ] `pwn rop`: ROP 가젯 검색
