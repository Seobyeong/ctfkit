# ROADMAP

ctfkit 개발 계획. 각 단계는 **통과 조건(Gate)** 을 만족해야 다음 단계로 넘어간다.
> 원칙: 미완성인 큰 프로젝트보다, 완성된 중간 규모 프로젝트가 낫다.
> Gate를 통과하지 못하면 다음 버전으로 가지 않고 현재 버전을 마무리한다.

## 방향 (2026-10-28 재설정)

**CTF 풀이에 필요한 작업 대부분을 한 CLI에서 해결하는 올인원 도구로 만든다.**
단순히 동작하는 데 그치지 않고, 포트폴리오로 내보일 수 있는 품질(플러그인 구조, 테스트, 문서, 패키징)까지 목표로 한다.

- 핵심: 암호 해독(완료)에 더해 `web`(HTTP·curl·퍼징), `forensic`(파일 분석), `hash`(해시 공격), `workspace`(작업 관리)를 한 명령 체계로 묶는다.
- 깊이: `auto` 자동 해독 엔진은 탐색 알고리즘(BFS/빔 서치) + 점수 함수 + 고전 암호 키 추정(`crack`)으로 계속 다듬는다.
- 넓이: 모든 모듈이 같은 플러그인 레지스트리를 공유한다. 디코더·분석기 하나 추가가 10줄 내외가 되도록 설계해, 범용성은 구조의 부산물로 얻는다.
- 확장: 여유가 있으면 `binary`(ELF 보호 기법·ROP 가젯), `rev`(디스어셈블), `jwt`, 진법 변환을 더한다. 밀리면 가장 먼저 포기한다.
- 마감: **2026-12-06 (일) 23:59**

## 개발 방식

수업에서 강조한 "AI로 작성된 코드를 리뷰·수정·개선하는 개발"을 그대로 따른다.

1. **AI 작성:** 기능 단위로 AI(Claude Code)가 코드와 테스트를 작성한다.
2. **사람 리뷰:** 내가 코드를 읽고 이해한 뒤, 버그·설계 문제·이해 안 되는 부분을 리뷰로 남긴다.
3. **수정·개선 요청:** 리뷰 결과와 추가하고 싶은 기능을 AI에 요청하고, 반영된 결과를 다시 리뷰한다.
4. **기록:** 매 사이클마다 devlog에 *요청한 것 / 리뷰에서 발견한 것 / 배운 것*을 남긴다.

> README에 AI 활용 사실과 참고한 기존 도구(CyberChef "Magic", Ciphey, curl, binwalk 등)를 명시한다.

## 알려진 한계 (깊게 팔 후보)

- **짧은 비즈네르 암호문:** 약 250바이트 이상이면 대부분 풀리지만, 100바이트 안팎에서는 열마다 글자가 적어 카이제곱이 불안정하고 키 일부가 틀린다.
  개선 후보: 바이그램·쿼드그램 통계로 점수 매기기, 키를 한 글자씩 바꿔 보며 점수를 올리는 언덕 오르기(hill climbing).
- **짧은 플래그만 XOR 된 경우:** 플래그 접두사로 시작하면 알려진 평문 공격으로 풀리지만, 접두사가 없거나 중간에 있으면 통계적 추정이 약하다.
- **점수 함수의 임계값**(`SOLVED_THRESHOLD`, XOR `ENGLISH_THRESHOLD` 등)은 예제로 맞춘 값이다. 더 많은 실제 문제로 검증이 필요하다.
- **`web` 안전성:** 허용 도메인 목록(워게임 인스턴스·localhost) 밖으로는 요청을 보내지 않고, 반복 요청에 속도 제한과 총량 상한을 둔다. 학습 목적 외 사용은 하지 않는다.
